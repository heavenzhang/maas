# MatrixCube MaaS · 多角色交互原型 v0.2

直接打开 [index.html](./index.html) 即可体验。它是纯前端、本地状态驱动的交互样机；不需要账号、安装依赖或连接后台。右上角可切换“开发者 / 模型管理员 / 平台运营”，也可“重置演示”。浏览器刷新后保留模拟状态；重置会清除本原型的本地演示数据。

建议按以下路径体验：

1. **开发者**：模型目录看详情 → Key 与审批发起申请 → 调用工作台尝试调用。未获批时会给出恢复入口。
2. **平台运营**：Key 与审批批准 → 渠道管理调整主备 → 预算调整限额 → 用量与账单查看同一演示请求；在对账页体验“差异登记 → 模拟更正 → 重核”。
3. **模型管理员**：部署管理选择 GPU-A/NPU-B/DCU-C 演示资源分组并创建服务 → 模拟就绪后从开发者模型目录核对 → 资源池查看分组占用 → 训练任务提交与优先级调度 → 监控查看关联服务和请求的演示告警。
4. 回到开发者工作台，观察渠道故障切换、预算不足和全部渠道停用后的失败/恢复状态；切换向量模型可看到独立的 `/v1/embeddings` 示例与向量样例。页面中的请求标识在响应、用量和账单视图间保持一致。

界面共 13 个工作视图，覆盖模型目录、访问授权、调用、用量、部署、异构算力池、训练任务、监控、渠道、预算、账单和安全运维。这里的 216 张卡、服务、用量、金额和告警全部是虚构数据，只用于验证 200 卡量级的信息架构；没有真实资源纳管、模型推理、审批、计费或漏洞修复。

## 验证

当前测试脚本位于 [test-prototype.cjs](./test-prototype.cjs)，基于 Playwright。若本机已安装 Playwright，可在此目录运行：

```bash
python3 -m http.server 8766
PROTOTYPE_URL=http://127.0.0.1:8766/ node test-prototype.cjs
```

本轮已验证三类角色的主要路径、跨页标识、未就绪模型隔离、文本/Embedding 调用形态、资源分组占用、告警对象、差异核对、预算不足恢复、渠道主备切换、20 个移动端视图检查、`file://` 直接打开与浏览器错误检查。截图在 [evidence](./evidence/)；对标与验收范围见 [scope-and-benchmarks.md](./scope-and-benchmarks.md)。

## 实施边界

本地模拟流程 ≠ 开源组件已整合。预期技术关系中，New API 负责模型渠道/Key 入口候选，SGLang 负责私有模型推理，KServe 是服务生命周期候选，Volcano 是训练与批任务调度候选，APISIX 是外部 API 入口候选；摩度业务控制面承担跨组件的组织、审批、预算与正式账本。这些均需独立 PoC 和真实数据链路验证。NPU/DCU 与推理引擎的实际兼容性、告警数据、供应方对账回单也都没有验证或接入。来源与不确定性见 [product-facts.md](./product-facts.md)。

代码示例中的 `maas.example.invalid` 为不可访问占位域名；请勿输入真实凭据或敏感业务资料。本目录不是生产部署包，也不是正式报价或运行指标。下一阶段应先完成组件版本与接口契约、真实 SGLang 推理/流式输出和 New API 渠道联调，再接入身份、预算、审计与资源调度。
