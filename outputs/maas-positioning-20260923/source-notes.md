# 摩度 MaaS 调研与定位 - 来源与方法笔记

## 决策问题

支持摩度管理层决定：是否应该建设 MaaS，应复用哪些开源层，应自研什么，以及如何避免和云厂商、推理引擎、通用 Agent 平台正面竞争。

## 范围与时点

- 公开资料截止：2026-09-23（Asia/Shanghai）。
- 开源层：推理引擎、serving/编排、模型网关、边缘/私有化、应用层参考。
- 商业定位：区域政府/园区、智算中心/IDC/运营商、集团企业、行业集成商。
- 本次不包含市场规模测算、客户访谈、内部合同/成本分析和生产性能测试。

## 证据库

- GitHub 仓库首页、README、LICENSE 和 REST 元数据，用于核对定位、许可证、stars、归档状态与最近活动。
- 华为云 MaaS、火山方舟、硅基流动官方产品页，用于判断市场已普遍覆盖的模型 API/部署/评测/精调能力。
- 北京亦庄、上海、苏州、深圳官方文件，用于验证模型券/Token 券在准入、抵扣、核销、运营、审计和绩效方面的实际需求。
- `算力管理平台-第四册技术部分.pdf.pdf`，重点复核 PDF 页 20-31（文内页码 288-299），用于建立资源池、模型生命周期、路由、弹性、多引擎、多模态、GPU 容器、Volcano 调度、优先级和漏洞修复参考基线。

## 可视化合同

- 报告段落：开源版图。
- 问题：哪些项目有较大的当前社区体量？
- 形式：水平 bar，类别为项目，数值为 GitHub stars。
- 解读边界：stars 仅是社区信号，不用于性能、生产可用性或商业成熟度排名。
- 数据集：`oss_projects`，保留层级、License、状态和摩度建议字段供审阅。
- 配色：单一非中性蓝色根，无冗余图例；条形从零开始。

## 结论边界

- 指定的 `heavenzhang/maas` 是空仓库，无代码、README、License、commit 或 Release。
- 产品定位、客群优先级与五层架构是结合公开证据和摩度既有业务叙事形成的策略建议，不是已核实产品现状或销售预测。
- 政府文件证明类型化需求，不代表摩度必然中标、具备资质或获得收入。
- 许可证结论需在固定依赖版本后生成 SBOM 并由法务复核。

## 执行记录

- 执行模式：主控 + 3 个并行调研工作包。
- 参与角色：仓库现状核查、开源技术版图、市场/定位独立研究；主控负责证据复核、统一定位、参考 PDF 解读、报告集成和验收。
- 可确认模型：主控与子任务继承当前 Codex 会话默认模型；未显式切换或声称未核实的模型。
