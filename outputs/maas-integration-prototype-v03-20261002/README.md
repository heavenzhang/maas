# MatrixCube MaaS · 集成透视原型 v0.3

打开 [index.html](./index.html) 即可演示。所有状态保存在当前浏览器的 `localStorage`；点击右上角“重置演示”可从头开始。本目录是独立原型，未修改 v0.2。

## 建议演示路线

1. **模型管理员**：进入“模型与部署”，提交模拟部署，等待状态依次经过排队、创建、加载、健康检查、Ready；查看门户服务与 GPUStack 对象的拟议映射。
2. **平台运营**：进入“发布与授权”，将 Ready 的部署发布为模拟 New API 渠道。
3. **开发者**：提交项目 Key 申请；此时先进入“调用透视”发起一次调用，可看到未获授权的拒绝。
4. **平台运营**：批准申请并模拟签发 Key。回到开发者，发起调用；在“调用透视”查看关联 ID、各阶段、组件对象和模拟用量，再到“用量与审计”核对同一请求。
5. **平台运营**：勾选主渠道故障，分别在启用和关闭备份渠道时让开发者调用，观察恢复与失败；再勾选预算不足，观察请求在门户侧被拒绝、未产生成功用量事件。
6. 在“集成契约”查看每个字段的拟议权威来源、适配工作以及原生控制台的定位。

## 本版新增的可观察细节

- 一条业务链中，展示摩度门户、New API、GPUStack、SGLang 的职责与状态。
- 门户服务、部署、渠道、Key 申请、调用、用量事件使用稳定的演示对象标识；请求详情可回溯到用量表。
- 同一请求区分门户拒绝、上游失败、模拟备份恢复和成功执行；失败请求不会产生成功用量事件。
- 提供模型与渠道映射、权威系统、拟议 `correlation_id`、待核实接口事项，而不只是页面导航。
- 三种演示角色共享本地状态，刷新后仍可继续；角色切换不是真实身份认证。

## 事实与能力边界

这是纯前端、本地状态驱动的交互样机：**没有部署 GPUStack、SGLang、New API，没有真实模型、GPU、身份系统、审批、计量或账单**。`Qwen3-8B`、服务和渠道 ID、Token 数及费用都是演示值，不用于性能、成本或投标结论。组件间 `correlation_id` 透传是摩度拟议的集成能力，不是经核实的开源项目原生能力。原生控制台按钮仅显示占位说明，不访问外部后台。

页面顶部持续区分“门户界面可交互 / 编排与运行本地模拟 / 真实接口未接入 / 生产能力未验证”。官方产品依据及拟议部分见 [product-facts.md](./product-facts.md)，视觉资产见 [brand-spec.md](./brand-spec.md)。

逐角色验收范围见 [acceptance-matrix.md](./acceptance-matrix.md)，本次执行与验证记录见 [execution-record.md](./execution-record.md)。
